# Arcade Atlas automatic high scores

The first integration supports the locally hosted **2048** game. The leaderboard keeps its existing historical entries and adds submitted online scores.

## 1. Create the database

Create a Supabase project, open its SQL Editor, and run:

```sql
create table if not exists public.scores (
  id bigint generated by default as identity primary key,
  player_name text not null check (char_length(player_name) between 1 and 24),
  game_title text not null check (char_length(game_title) between 1 and 60),
  score bigint not null check (score >= 0 and score <= 1000000000),
  created_at timestamptz not null default now()
);

alter table public.scores enable row level security;

create policy "Anyone can read scores"
on public.scores for select
to anon, authenticated
using (true);

create policy "Players can submit scores"
on public.scores for insert
to anon, authenticated
with check (
  char_length(player_name) between 1 and 24
  and char_length(game_title) between 1 and 60
  and score >= 0
  and score <= 1000000000
);
```

## 2. Add the public project settings

Open `js/arcade-score-config.js` and replace the two placeholders with the Supabase **Project URL** and **publishable/anon key** from Project Settings → API.

Only use the publishable/anon key in this browser file. Never put a Supabase `service_role` key in site JavaScript or GitHub.

## 3. Deploy and test

After the config is saved and the site is deployed:
1. Sign in to Arcade Atlas.
2. Open the locally hosted 2048 game.
3. Finish a round. The score is sent automatically when the game is won or ends.
4. Open the leaderboard and refresh to see submitted scores.

## Important limitations

- This first integration only collects scores from the locally hosted 2048 game. Most other games are embedded or third-party builds and do not expose a reliable score event to the site.
- The current Arcade Atlas accounts are stored in each browser's local storage. The submitted player name is therefore a display name, not verified identity.
- Browser-submitted scores can be forged. The database rules validate basic fields, but they do not prove that a score was legitimately earned. A cheat-resistant leaderboard would require server-side game validation or a trusted game integration.
- Until the Supabase project is configured, score submission and online score loading remain inactive; the existing historical leaderboard continues to display.
